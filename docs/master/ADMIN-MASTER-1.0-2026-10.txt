Règle d’architecture — Tous les écrans humains et tous les agents internes consomment les mêmes services métier. La logique critique n’est jamais enfermée dans le frontend.
 |

1. Vision et principes non négociables
iAgent doit gérer une flotte de postes de travail IA, des agents loués, des compétences, des connecteurs, de la voix, des abonnements, des clients et une société interne elle-même opérée par des agents.
Principe
 | Exigence
 | P1 — Un seul cerveau
 | Fleet, Platform et Team sont trois consoles branchées sur le même iAgent Core, la même identité, le même Policy Engine, le même Event Bus et le même Audit.
 | P2 — API first
 | Chaque action importante existe côté service/API avant d’exister comme bouton. Les agents internes utilisent l’Action Gateway.
 | P3 — Actors unifiés
 | Humains, agents, services et devices sont identifiables, autorisables et auditables.
 | P4 — Desired State
 | Le cloud décrit l’état attendu ; la Box remonte l’état réel ; le Device Agent réconcilie.
 | P5 — Sécurité par défaut
 | mTLS, Vault, certificats, chiffrement, least privilege, approvals, audit.
 | P6 — Données client séparées
 | Les données client restent isolées ; les skills généralisables suivent un pipeline de revue.
 | P7 — Échelle
 | Toute fonction est conçue pour batch, canary, limites, reprise, observabilité et automatisation.
 |

1.2 Anti-patterns interdits
Une base différente par Desktop.
Un mot de passe admin partagé.
Un agent Support avec SSH/root direct.
Une logique tarifaire dupliquée dans les frontends.
Une mise à jour globale sans canary/rollback.
Des tokens OAuth visibles dans le frontend.
Un agent interne qui agit hors Action Gateway/Audit.
Une résiliation qui détruit instantanément les données.

22. Critères d’acceptation
Device simulator enroll + cert + heartbeat + desired state.
Fleet affiche la Box et lance un diagnostic audité.
Rollout canary + auto rollback.
Platform crée tenant + box assignment + agent + entitlement.
Suspension agent modifie entitlement et Box converge.
Internal Support Agent demande restart_voice via Action Gateway.
Policy Engine autorise/refuse selon rôle/tenant/risque/seuil.
High-risk action waits for approval.
Every action has audit + correlation.
Payment failure enters grace, no immediate deletion.
Connector secrets never returned to frontend.
Factory run report linked to device.
RMA replacement creates new cryptographic identity.
