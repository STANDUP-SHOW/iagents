1. Principes non négociables

-   Ne pas réécrire la base existante : conserver métiers, agents,
    fonctions, secteurs, logiciels, relations, filtres, routes et
    logique métier.

-   Séparer DATA LAYER, BUSINESS LOGIC, UI LAYER et CONTROL PLANE.

-   Aucun tarif public ne doit être codé en dur dans le front : plans,
    options, consommation et remises doivent être administrables et
    versionnés.

-   Les anciennes simulations tarifaires serveurs/multibox haut de gamme
    sont conservées en interne mais masquées du public pour l’instant.

-   Les architectures locales avancées, clusters, multi-Box et fortes
    puissances restent « Sur devis / Contacter iAgent ».

-   iAgent Business et iAgent Home partagent la technologie mais pas le
    funnel, les messages ni la direction artistique.

-   Le client voit le travail, les résultats et les validations ; le
    savoir-faire propriétaire (prompts système, orchestration, Skills,
    secrets, connecteurs internes) reste protégé.

  -----------------------------------------------------------------------
  Principe : le client contrôle le travail ; iAgent protège le
  savoir-faire.

4. iAgent Workforce / Box

La Box doit être vendue comme une appliance iAgent louée, jamais comme
un mini-PC vendu.

-   Matériel cible : mini-PC boosté, écran tactile, clavier/souris de
    secours, pavé/tablette de signature, enceinte de qualité, micro
    conférence/studio longue portée.

-   Desktop Commander préinstallé, agents et connexions configurés,
    profils vocaux et permissions chargés selon contrat.

-   Maintenance, mises à jour, remplacement et support selon offre.

-   La Box reste propriété de iAgent : restitution, renouvellement ou
    rachat éventuel.

-   Box Business sombre/graphite ; Box Home blanche/clair, tout en
    maximisant la réutilisation des composants.

  -----------------------------------------------------------------------
  Expérience cible : courant + réseau → connexion → l’équipe est là.

6. Protection, licences et Control Plane

-   Ne pas livrer un Windows classique avec admin ouvert. Viser une
    appliance verrouillée : Linux/Ubuntu Core si compatible ; sinon
    Windows IoT/Enterprise restreint.

-   TPM 2.0, Secure Boot, disque chiffré, OS signé, mises à jour
    contrôlées.

-   Identité cryptographique unique par Box et mTLS vers le Control
    Plane.

-   Chaque agent activé = entitlement Client + Box + Agent Template +
    Spécialisation + Licence.

-   Skill packages signés/chiffrés ; activation/révocation à distance ;
    clés non exportables.

-   Si abonnement stoppé, agent non exécutable ; copie disque inutile
    sur une autre machine sans identité matérielle.

-   Actions auditées côté client ; logique propriétaire non exposée.

Control Plane – fonctions minimales

-   Provisioning Box et inventaire

-   Licences / entitlements

-   Déploiement / révocation agents

-   Updates OS / Desktop / Skills

-   Télémétrie machine

-   Remote support

-   Voice registry et provider routing

-   Facturation consommation

-   Audit sécurité

-   Gestion versions Skills

7. Skill Packs, apprentissage et confidentialité

L’apprentissage terrain est un actif majeur, mais la gouvernance doit
séparer connaissance généralisable et données client.

  -----------------------------------------------------------------------
  Type                                Règle
  ----------------------------------- -----------------------------------
  Données client                      Emails, fichiers, contrats, prix,
                                      clients, documents et secrets
                                      restent au client.

  Mémoire instance                    Isolée par tenant, avec
                                      export/suppression selon politique.

  Connaissance généralisable          Workflow abstrait / connaissance
                                      logiciel / procédure non spécifique
                                      : candidat Skill Pack après
                                      validation.

  Skill Pack                          Versionné, signé, testé, scoped par
                                      métier, secteur, outil, locale.
  -----------------------------------------------------------------------

-   Créer skill_pack_id, version, source_type, validation_status,
    compatible_agents/tools, sector_scope, locale, changelog.

-   Workflow de revue avant diffusion à d’autres clients.

-   Aucun contenu confidentiel ne devient Skill Pack par défaut.

-   Prévoir opt-in et anonymisation quand une entreprise participe
    volontairement à l’amélioration commune.

10. iAgent Voice : couche vocale multi-provider

Voice existe déjà dans Desktop Commander mais ne doit plus être couplé à
une clé Gemini unique.

-   Créer une abstraction Voice Provider : Gemini Live, ElevenLabs, puis
    fournisseurs futurs/local.

-   L’utilisateur choisit l’identité vocale ; iAgent choisit le moteur
    selon qualité/coût/langue/disponibilité.

-   Modes possibles : quality_first, cost_first, balanced, local_first.

-   Voice Registry stable par persona pour conserver la même voix sur
    Desktop, téléphone et support.

-   La logique métier ne dépend jamais d’un provider unique.

  -----------------------------------------------------------------------
  Méthode conceptuelle                But
  ----------------------------------- -----------------------------------
  startSession()                      Initialiser

  sendAudio()/receiveAudio()          Streaming bidirectionnel

  interrupt()                         Interruption naturelle

  setVoice()                          Profil vocal

  sendContext()                       Contexte tenant/agent

  executeTool()                       Tool calling

  closeSession()                      Fin + métriques
  -----------------------------------------------------------------------

11. Téléphonie, standard et human handoff

Architecture principale : numéro virtuel + SIP + iAgent Voice Gateway.
Pas de carte SIM comme fondation.

-   Un ou plusieurs numéros E.164 par entreprise.

-   Standard conversationnel libre ; pas besoin de DTMF comme interface
    principale.

-   Chaque agent peut avoir extension interne et département.

-   Transfert agent→agent, hold, musique, callback, voicemail.

-   Handoff humain : identité appelant, motif, résumé, Prendre / Refuser
    / Rappeler / Laisser l’agent continuer.

-   Transfert vers Desktop/WebRTC/mobile/fixe selon règles.

-   PhoneProvider adapter : Telnyx, Twilio, SIP générique.

  ----------------------------------- -----------------------------------

18. Sécurité / conformité / observabilité

-   Isolation par tenant.

-   Secrets chiffrés ; jamais dans l’UI ou les logs.

-   Consentement/enregistrement téléphonique configurables par pays.

-   Règles appels sortants : consentement, do_not_call, horaires, source
    de preuve.

-   Audit horodaté pour actions sensibles.

-   Rétention configurable.

-   Monitoring Box / Voice Hub / Control Plane.

-   Escalade humaine et kill switch.

-   Défense en profondeur, sans promesse de sécurité absolue.
